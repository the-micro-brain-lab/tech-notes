Supabase × Cloudflare

Một khuôn để đưa app web lên Supabase (đăng nhập, Postgres) và Cloudflare (Worker, R2). Mọi app theo khuôn này có cùng flow, cùng cơ chế và cùng cấu trúc thư mục, nên chép được từ app này sang app khác.

  • React + Vite PWA
  • Workers + Hono
  • R2
  • Cron Triggers
  • Auth · email OTP
  • Postgres + RLS
  • GitHub Actions
App đang dựng Điền vào đây, mọi lệnh và file mẫu bên dưới đổi theo. Tiến độ checklist lưu riêng cho từng app.

WhatWhere hôm nay (4/10/2026, main 0bcccd6)

  • Đã có: code web và Worker, 18 migration, test pgTAP, ci.yml, deploy.yml, scripts/smoke.sh.
  • Chưa deploy lần nào (T1.12 còn mở). Quy trình deploy chưa chạy thật: bước lấy URL và db push không tương tác chưa được kiểm.
  • Còn trống: tên model Gemini, binding RATE_LIMITER, xoá file mồ côi trên R2 (đang tắt), giới hạn gói household, chỗ trống trong LAUNCH.md.

01Kiến trúc

Một Worker phục vụ cả giao diện lẫn API trên cùng một tên miền, nên không cần CORS. Trình duyệt nói thẳng với Postgres cho dữ liệu thường, RLS là hàng rào. Worker chỉ làm những việc cần bí mật, cần file, hoặc tốn tiền.

02Bảy cơ chế cốt lõi

Đây là phần chép nguyên sang app khác. Mỗi cơ chế ghi file tham chiếu trong repo WhatWhere.

Đăng nhập bằng email OTP Supabase

Một email chứa cả link và mã 6 số. Trên iPhone, link mở Safari chứ không mở app PWA đã cài, nên người dùng gõ mã vào app. Web dùng signInWithOtp và verifyOtp của supabase-js, luồng implicit mặc định.

Tham chiếu: apps/web/src/lib/supabase.ts, lib/backend.ts, supabase/templates/sign_in.html

Worker kiểm JWT bằng JWKS Worker

Worker không gọi DB để biết ai đang gọi. Nó kiểm chữ ký bằng khoá công khai của Supabase, issuer phải khớp tuyệt đối, audience là authenticated. Chỉ nhận khoá bất đối xứng (ES256); token HS256 bị từ chối.

middleware/auth.ts (rút gọn)
const issuer = `${env.SUPABASE_URL}/auth/v1`;
const jwks = createRemoteJWKSet(new URL(`${issuer}/.well-known/jwks.json`)); // cache theo isolate
const { payload } = await jwtVerify(token, jwks, {
  issuer,
  audience: 'authenticated',
  requiredClaims: ['exp', 'sub'],
});
c.set('user', { id: payload.sub, token }); // lỗi → 401 {"error":"unauthorized"}

Tham chiếu: apps/worker/src/middleware/auth.ts

Dữ liệu chia theo tenant, RLS là hàng rào Postgres

Mọi bảng có cột tenant (WhatWhere: household_id). Bảng con dùng khoá ngoại ghép (household_id, id). anon không có quyền gì. Quyền của authenticated bị thu hết rồi cấp lại theo từng cột, nên RLS không phải lớp chặn duy nhất. Bảng mà web không được ghi (thành viên, quyền, hạn mức) chỉ đổi qua RPC security definer với search_path = ''.

Mẫu migration RLS
create function public.auth_tenant_id() returns uuid
language sql stable security definer set search_path = '' as $$
  select m.tenant_id from public.members m where m.user_id = auth.uid()
$$;

alter table public.notes enable row level security;
revoke all on public.notes from anon, authenticated;
grant select, delete on public.notes to authenticated;
grant insert (tenant_id, body), update (body) on public.notes to authenticated;
create policy notes_rw on public.notes for all to authenticated
  using (tenant_id = public.auth_tenant_id())
  with check (tenant_id = public.auth_tenant_id());

Tham chiếu: supabase/migrations/0002_rls.sql, supabase/tests/rls_*.test.sql

Hai client Supabase trong Worker Worker

userClient(env, token) dùng publishable key cộng JWT của người dùng, nên RLS vẫn áp dụng. Mọi việc làm thay người dùng đi qua client này. serviceClient(env) dùng secret key, vượt RLS, chỉ dành cho việc nền (xử lý AI, cron) và trừ hạn mức.

Tham chiếu: apps/worker/src/lib/supabase.ts, lib/pipeline-db.ts

File private trên R2 R2

Key không lưu trong DB mà suy ra từ dữ liệu: {tenant}/{sha256}-{full|thumb}.{ext}. Client tự thu nhỏ ảnh và tính SHA-256. Worker tính lại để đối chiếu, kiểm kích thước và hạn mức, ghi R2, rồi chèn dòng DB bằng JWT người dùng. Khi xem, Worker tìm dòng bằng RLS trước (tìm thấy nghĩa là có quyền), rồi trả file với Cache-Control: private, immutable. Thẻ <img> không gửi được header Authorization, nên web tải blob kèm token rồi cache trên máy.

Tham chiếu: apps/worker/src/routes/photos.ts, lib/r2.ts, apps/web/src/lib/api/photo-url.ts

Hạn mức chỉ thi hành ở Worker RPC Worker

Bảng plans (giới hạn dạng jsonb), grants theo người, ai_usage theo kỳ. Hàm household_entitlement() gộp quyền của mọi thành viên. Worker gọi reserve_ai_credit trước khi gọi AI và release_ai_credit khi lỗi, bằng service role. Hết hạn mức thì giảm chức năng (đánh dấu chờ, tìm kém thông minh hơn), không báo lỗi.

Tham chiếu: supabase/migrations/0003_functions.sql, 0004_plans.sql, docs/SPEC.md mục 8c

Hợp đồng lỗi và lớp Backend web

Worker luôn trả {"error": "<code>"} (unauthorized, rate_limited, too_large, read_only…). RPC báo lỗi bằng SQLSTATE (42501, 23505, 53400, P0002…). Web quy cả hai về một bộ mã BackendErrorCode. Giao diện chỉ thấy interface Backend, nên test dùng backend giả và chế độ demo (VITE_DEMO=1) chạy được không cần dịch vụ nào.

Tham chiếu: apps/web/src/lib/backend.ts, lib/backend-error.ts, src/dev/demo-backend.ts, packages/shared/src/api.ts

07Quy ước chung

Giữ giống nhau ở mọi app để chép code qua lại không phải sửa.

  • Cùng origin. Một Worker phục vụ cả SPA và /api. Không CORS, không subdomain riêng cho API.
  • Migration đặt tên NNNN_tên.sql, đầu file ghi hợp đồng (bảng, hàm, ai được gọi). Chỉ tiến, không có file rollback.
  • Mỗi policy RLS và mỗi RPC có test pgTAP trong supabase/tests/. CI chạy supabase test db.
  • Hàm mới: thu quyền EXECUTE mặc định rồi cấp lại rõ ràng cho đúng role.
  • packages/shared chứa hợp đồng API bằng zod, giới hạn và enum dùng chung cho web và Worker. Xuất thẳng TypeScript, không cần build.
  • Lỗi: Worker trả {"error": code}, RPC dùng SQLSTATE, web quy về một bộ mã duy nhất.
  • Log: một dòng JSON mỗi request, không ghi token hay email.
  • Commit theo Conventional Commits, scope web, worker, db, shared, docs, tools.
  • Câu hỏi còn mở ghi vào docs/QUESTIONS.md; quyết định đã chốt nằm trong mục 2 của docs/SPEC.md.
  • Cổng dev cố định với strictPort, mỗi app một khối cổng (mục 04).

08Bẫy đã gặp

Mỗi mục đều đã tốn thời gian ở WhatWhere. Cách tránh ghi ngay bên dưới.

  1. Issuer của JWT phải khớp tuyệt đối.

    Local dùng http://127.0.0.1:54321 ở cả web và Worker. Mở web bằng localhost thì token mang issuer khác và Worker trả 401.

  2. db push không chạy seed.sql.

    Dữ liệu tham chiếu mà production cần (gói, danh mục) phải nằm trong migration.

  3. Jurisdiction của R2 không đổi được.

    Chọn sai vùng thì phải tạo bucket mới và chép dữ liệu.

  4. Thẻ <img> không gửi được Authorization.

    Tải blob bằng fetch có token rồi dùng object URL, cache trên máy. Hoặc dùng signed URL nếu chấp nhận link lộ ra được.

  5. Supabase Free tạm dừng project sau 7 ngày không có request.

    Cron của Worker ping DB mỗi 15 phút.

  6. Biến VITE_* được nhúng lúc build.

    Đổi giá trị thì phải build và deploy lại. Secret không bao giờ được có tiền tố VITE_.

  7. Thiếu run_worker_first: ["/api/*"] thì SPA fallback nuốt API.

    /api/abc trả về index.html thay vì JSON. Smoke test kiểm đúng điều này bằng /api/nope.

  8. Service worker của PWA cũng nuốt /api.

    Thêm navigateFallbackDenylist: [/^\/api\//] và không precache gì dưới /api.

  9. Link đăng nhập mở Safari, không mở PWA trên iPhone.

    Email gửi kèm mã 6 số ({{ .Token }}) và màn đăng nhập có ô nhập mã.

  10. Queues cần gói Workers Paid.

    Dùng ctx.waitUntil cho việc nền, cron quét lại việc bị kẹt.

  11. Supabase cấp quyền EXECUTE mặc định cho mọi function mới.

    Hàm chỉ dành cho service role vẫn gọi được từ web nếu quên thu quyền.

  12. Hai stack Supabase local cùng lúc đụng nhau.

    Đổi project_id và các cổng trong config.toml; app thứ hai còn cần cổng wrangler dev và proxy Vite riêng.

  13. Điện thoại trong mạng LAN cần HTTPS.

    crypto.subtle, crypto.randomUUID và micro chỉ có trong secure context. Chế độ dev:demo:lan dùng chứng chỉ tự ký.

Dữ liệu chia theo đơn vị nào?household, mỗi người một nhàĐổi tên cột tenant (team_id, workspace_id) và helper RLS. Nhiều tenant mỗi người thì helper trả về tập id.
Đăng nhập thế nào?Email OTP (link + mã)Thêm OAuth ở Supabase; Worker không đổi vì vẫn kiểm JWT như cũ.
Có file không?Có: ảnh hai cỡ trên R2Không có thì bỏ binding R2 và route file.
Có gọi API trả phí không?Gemini, qua WorkerGiữ mẫu reserve/release hạn mức; đổi adapter.
Có gói và hạn mức không?plans, grants, mã kích hoạtKhông có thì bỏ 0003, 0004, 0014 và phần entitlement.
Cần chạy offline không?Có: Dexie + outboxKhông cần thì bỏ lib/offline, lib/outbox.
